# Follow-on work

## Before the first production deployment

Run the live acceptance gates, correct vendor-runtime incompatibilities without relaxing security, pin tested image digests and complete a real encrypted restore drill. Connect the administrator laptop to the existing VPN separately. Then validate backend connectivity from the node proxy and enable the currently disabled example routes.

## Trigger-based enhancements, not promised features

- More administrators or independently trusted nodes: reviewed enrollment/EAB, finer authorization and external identity management.
- Availability objectives beyond a single VPN hub: redundant DNS and CA recovery strategy; never run unsafely shared ACME/CA databases.
- Frequent inventory edits: transactional live-config reconciliation with robust rollback and validation before reducing maintenance downtime.
- Managed customers: explicit commercial support/licensing, per-customer installation lifecycle and secret storage.
- Stronger supply-chain requirements: signed releases, SBOM, digest policy, scanned artifacts and dependency locking with verified hashes.
- Additional platforms/protocols: separately tested IPv6/rootless, upstream mTLS and richer service routing schemas.

Do not add a management web application, Kubernetes, multi-tenant CA or remote agents merely to increase feature count.
